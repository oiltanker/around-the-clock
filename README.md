# Around The Clock — source tree

A Timberborn mod that adds a shift-mode dropdown to every workplace panel:
Regular (vanilla), Two shifts (2×12h, as in eMka's Second Shift), or Three shifts
(3×8h, 3× workers). This directory holds only the build; the installable mod lives
at `..\around-the-clock\` (sibling folder).

## Layout

```
build.ps1              build orchestration (publicize -> compile -> optional deploy)
AroundTheClock.Core/      game logic components (ShiftWorkplace, WorkerShiftHours, WorkerPositionFixer)
AroundTheClock.Patching/  Harmony patches
AroundTheClock.CoreUI/    entity-panel UI (native dropdown + shift viewer)
tools/Publicizer/      Cecil tool that makes game assemblies fully public for compile-time use
tools/AccessAudit/     Cecil audit of non-public game API access (must stay at 3 base-ctor false positives)
tools/AccessInjector/  post-build IgnoresAccessChecksTo injector (kept for reference; Unity Mono ignores it)
assets/                midday-shift.png icon + generator script
lib_public/            publicized copies of game assemblies (generated, not committed)
```

## Save compatibility

Save data is keyed by explicit strings, not class names — the rename kept every
serialization key (`TwoShiftsWorkplace` component key, `ShiftCount`, legacy
`TwoShiftsEnabled`), so saves made by any version (original mod, Three Shifts fork,
Around The Clock) load interchangeably. Harmony ids changed (`Oiltanker.AroundTheClock`);
never enable this alongside the original Second Shift or the Workplace Schedules
family (duplicate patches on `Workplace` / `WorkerWorkingHours`).

## Build

Requires .NET SDK 8 (per-user install at `%USERPROFILE%\dotnet-sdk` suffices; build.ps1 sets
`DOTNET_ROOT`). Game must be at the default Steam path (`build.ps1` `$gameDir`).

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1            # compile only
powershell -ExecutionPolicy Bypass -File build.ps1 -Deploy    # compile + install into the mod folder
```

What `build.ps1` does:
1. Builds `tools/Publicizer` and runs it on 10 game assemblies into `lib_public\`
   (compile-time only; private-member access matches how the upstream author used
   Unity-publicized assemblies — the mod itself ships no game DLLs).
2. Builds `AroundTheClock.Core`, `AroundTheClock.Patching`, `AroundTheClock.CoreUI` (netstandard2.1).
3. With `-Deploy`, copies the three DLLs to
   `..\around-the-clock\version-1.1\Scripts\` and
   `assets\midday-shift.png` to `version-1.1\Assets\`.

## Constraints

- This build tree must stay OUTSIDE the mod folder: the game loads every `*.dll` recursively
  under a mod directory, and `bin/`, `obj/`, `lib_public/` are full of DLLs that would crash it.
- Asset bundles (UXML/USS/sprites) are reused from the shipped mod unchanged — Unity-built
  binaries are not rebuilt; all UI additions are constructed in C# code. Bundle-owned names
  (`Game/EntityPanel/TwoShiftsWorkplaceFragment`, `TwoShiftsWorkersToggleWrapper`,
  `TwoShiftsToggle`, sprite names, loc key `SecondShift.TwoShiftsToggle`) must not be renamed.
